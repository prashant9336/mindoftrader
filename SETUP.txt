================================================
  MINDOFTRADER — SETUP GUIDE
================================================

PREREQUISITES
-------------
- Node.js 18+
- npm or yarn
- Supabase account (free tier works)
- Vercel account (for frontend)
- Railway account (for backend)

================================================
STEP 1: DATABASE (SUPABASE)
================================================

1. Go to supabase.com → New project
2. In SQL Editor, run: database/schema.sql
3. Optional: Run database/seed.sql for demo data
4. Get your keys from: Settings → API
   - Project URL → NEXT_PUBLIC_SUPABASE_URL
   - anon/public key → NEXT_PUBLIC_SUPABASE_ANON_KEY
   - service_role key → SUPABASE_SERVICE_KEY (backend only)

================================================
STEP 2: FRONTEND (LOCAL DEV)
================================================

cd frontend
npm install

# Copy env file
cp .env.local.example .env.local

# Fill in .env.local:
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key
NEXT_PUBLIC_WS_URL=ws://localhost:4000
NEXT_PUBLIC_DEMO_USER_ID=demo-user-123

npm run dev
# Opens at http://localhost:3000

================================================
STEP 3: BACKEND (LOCAL DEV)
================================================

cd backend
npm install

# Copy env file
cp .env.example .env

# Fill in .env:
PORT=4000
FRONTEND_URL=http://localhost:3000

npm run dev
# WebSocket at ws://localhost:4000

================================================
STEP 4: DEPLOY FRONTEND (VERCEL)
================================================

cd frontend
npx vercel

# Set env vars in Vercel dashboard:
# NEXT_PUBLIC_SUPABASE_URL
# NEXT_PUBLIC_SUPABASE_ANON_KEY
# NEXT_PUBLIC_WS_URL  (your Railway backend URL, e.g. wss://your-app.railway.app)

================================================
STEP 5: DEPLOY BACKEND (RAILWAY)
================================================

1. Push backend/ to a GitHub repo
2. Go to railway.app → New project → Deploy from GitHub
3. Set env vars:
   PORT=4000
   FRONTEND_URL=https://your-vercel-app.vercel.app
4. Railway auto-detects Node.js and deploys
5. Get the Railway URL (e.g. https://xxx.railway.app)
6. Update NEXT_PUBLIC_WS_URL in Vercel to: wss://xxx.railway.app

================================================
ARCHITECTURE OVERVIEW
================================================

frontend/           Next.js 14 App Router (Vercel)
├── app/            Pages + API routes
│   ├── page.tsx           Dashboard
│   ├── trade/page.tsx     Trade evaluator
│   ├── coach/page.tsx     Live coach (WebSocket)
│   ├── journal/page.tsx   Trade journal
│   └── api/               REST API routes
├── components/     UI components
├── lib/engines/    Core logic (Market Brain, Trade Permission, etc.)
├── hooks/          React hooks
└── types/          TypeScript types

backend/            Node.js + Express + WebSocket (Railway)
└── src/
    ├── index.ts           Express server
    ├── websocket/         WebSocket coach server
    └── engines/           Market brain + behavior logic

database/           Supabase PostgreSQL
├── schema.sql      Table definitions + RLS policies
└── seed.sql        Demo data

================================================
PHASE 2 UPGRADES
================================================

1. Replace mock market data with Yahoo Finance:
   npm install yahoo-finance2
   Update: frontend/lib/engines/marketBrain.ts

2. Add real OI data from NSE API or broker API

3. Add Supabase Auth for real user accounts

4. Add real-time subscriptions via Supabase realtime

5. Add push notifications for lock events

================================================
CORE MODULES
================================================

MARKET BRAIN
  Input:  price, VWAP, ATR, OI, time
  Output: TRENDING | SIDEWAYS | TRAP

TRADE PERMISSION ENGINE
  Input:  entry, SL, target, direction, market state
  Output: ALLOWED | RISKY | BLOCKED

BEHAVIOR ENGINE
  Input:  trade history, lock status
  Output: warnings, lock triggers, revenge detection

LIVE COACH
  WebSocket-based messages:
  - Market condition alerts
  - Behavioral coaching
  - Lock notifications

POST-TRADE TRUTH ENGINE
  Input:  completed trade + context
  Output: mistakes[], improvement_tips[], score
